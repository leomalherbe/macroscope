# OPEN-MU · Policy desk — interface de jeu pour la séance 6

Trois pages statiques (dossier `macroscope/` du site GitHub Pages du cours ; les anciennes adresses `macsim/…` redirigent vers les nouvelles en gardant le PIN ou la classe), un petit « serveur » Google Apps Script adossé à une Google Sheet (décisions, résultats, engagements, commentaires), et **le moteur de simulation OPEN-MU** (`macroscope/engine.js`, modèle stock-flux d'une union monétaire à N pays, change fixe vis-à-vis du reste du monde) qui tourne dans le navigateur de la console : aucune saisie manuelle, aucun logiciel tiers.

| Page | Pour qui | Rôle |
|---|---|---|
| `macroscope/desk.html` | les groupes (lien ou QR, aucun compte) | se connecter avec le PIN du groupe, soumettre le plan de warm-up (3 ans) ou les décisions de l'année, lire ses résultats, commenter, participer au conseil des ministres |
| `macroscope/admin.html` | vous | ouvrir/fermer les tours, publier un communiqué, **régler les chocs et faire tourner le modèle** (onglet *Run*), publier les résultats, classement, conseil, export CSV |
| `macroscope/board.html?class=…` | le vidéoprojecteur | état du tour, compte à rebours, communiqué, **réserves de change de l'union et alerte**, classement, engagements, « engagements vs décisions » |

Tout est en anglais côté étudiants (langue du cours).

---

## 1. Mise en place (une fois, ~15 minutes)

1. **Créer une Google Sheet vide** (par ex. « OPEN-MU – IFM 2026 ») depuis votre compte Google.
2. Menu **Extensions → Apps Script**. Effacer le contenu de `Code.gs`, **coller le contenu de `macroscope/Code.gs`**, enregistrer (icône disquette).
3. Dans la barre d'outils de l'éditeur, choisir la fonction **`setup`** puis **Exécuter**. Google demande d'autoriser le script (compte → « Avancé » → « Accéder à … (non sécurisé) » → Autoriser : c'est votre propre script, l'avertissement est normal). `setup` crée les onglets (Config, Groups, Decisions, Results, Pledges, Comments, Log) et génère la **clé administrateur**, visible dans l'onglet `Config` de la Sheet (et dans le journal d'exécution).
4. **Déployer → Nouveau déploiement** → type **Application Web** → Description libre → *Exécuter en tant que* : **Moi** → *Qui a accès* : **Tout le monde** → **Déployer**. Copier l'**URL de l'application Web** (elle se termine par `/exec`).
5. Dans le site : ouvrir `macroscope/config.js` et coller cette URL dans `API_URL`, commit, push. (Tant que `config.js` est vide, les liens « Student page » et les tickets PIN générés par la console contiennent l'URL du script en paramètre `?api=`, donc tout fonctionne aussi sans cette étape.)
6. Ouvrir `https://leomalherbe.github.io/internationalfinancialmacro/macroscope/admin.html`, coller l'URL et la clé, **Connect**. Créer la classe (**+ New class**), puis l'onglet **Groups** → **Add 7 default groups** (Allemagne, France, Italie, Espagne, Pays-Bas, Belgique, Autriche — les membres de l'union du modèle) → **Save groups**. Les PIN à 4 chiffres sont générés ; **Print PIN slips** imprime un ticket par groupe avec le lien.

À tester avant la séance : ouvrir la page étudiants avec un PIN depuis votre téléphone, soumettre un plan, le voir en vert dans l'onglet **Run**, cliquer **Run all submitted plans** puis **Save and publish all**, et voir les résultats arriver sur le téléphone.

> Après toute modification de `Code.gs` (nouvelle version de l'interface) : dans l'éditeur Apps Script, remplacer tout le contenu de `Code.gs` par le nouveau fichier, enregistrer, puis **Déployer → Gérer les déploiements → ✎ (modifier) → Version : « Nouvelle version » → Déployer**. L'URL ne change pas, rien à refaire côté site. Modifier les pages HTML ne demande rien de plus qu'un push. La console affiche la version du script dans son pied de page après connexion (**v1.10** = droits de douane (§13 : vote du tarif extérieur commun, tarif d'un pays sorti) ; v1.9 = sortie de l'union (§12 : décision `leave`, leviers du pays sorti, tour « retaliation ») ; v1.8 = mode arcade « duels » (classes de type `duel`, levier « taux directeur », lignes de paire `DUEL:p<k>`) ; v1.7 = sixième dimension « émissions » (colonne `emis` ajoutée en fin d'onglet Results) ; v1.6 = leviers écologiques du modèle v2.0 ; v1.5 = tour de vote de crise séparé et plafond d'austérité contrôlé par le backend ; v1.4 = votes annoncés au conseil ; v1.3 = votes dans les décisions ; v1.2 = chocs et lignes « union », sans les votes) ; « Unknown action » ou des chocs qui ne s'enregistrent pas signalent un script pas encore republié.

## 2. Déroulé de la séance (checklist)

**Warm-up (chaque groupe gouverne la France 3 ans, les autres membres ne bougent pas)**
1. *Run* : régler les **chocs** des années 1 à 3 (demande mondiale, taux de la banque centrale, confiance des ménages, propension à importer, dévaluation ; 0 = pas de choc) → **Save shocks**. Les mêmes chocs s'appliquent à tous les groupes.
2. *Control* : rédiger le communiqué (le choc, le temps imparti), puis **Open with timer** (10–15 min).
3. Les groupes soumettent leur plan (3 colonnes Année 1/2/3, variations relatives en % de la référence bornées à ±10, 4 leviers : demande publique, prestations, impôt sur le revenu, TVA) avec leur stratégie a priori (150 caractères minimum). Ils peuvent modifier jusqu'à la clôture ; seule la dernière soumission compte. Personne ne voit les décisions des autres pendant que le tour est ouvert.
4. **Close submissions**, puis *Run* → **▶ Run all submitted plans** : chaque plan est simulé seul (la France suit le plan du groupe, les autres membres restent à leur politique de référence). L'aperçu montre les 5 écarts, R et la décomposition propre / étranger / chocs ; **Save and publish all** (ou **Save as draft** pour relire d'abord dans *Results*). Chaque groupe voit alors ses trois années avec les lignes « of which », l'état de l'union (réserves, solde courant, change) et rédige son analyse a posteriori.

> Les chocs du warm-up et ceux de la partie sont **distincts** : en passant à la partie, l'éditeur de chocs de l'onglet *Run* repart de zéro pour l'année 1 (les chocs du warm-up restent enregistrés à part).
5. Pour le débrief : *Control* → cocher « show every group's warm-up results and plans to everyone » : le tableau comparatif apparaît chez les étudiants et sur le board.

**La partie (un pays par groupe, année par année)**
1. *Control* → **Start the game → year 1** (les soumissions sont fermées). *Run* : chocs de l'année 1 → **Save shocks**. Communiqué, puis **Open submissions** / **Open with timer**.
2. Quand vous le souhaitez : **Convene the council**. Les engagements sont publics (page étudiants + board) ; les décisions restent privées. Un engagement est une phrase, à laquelle le groupe peut attacher des chiffres (leviers) et/ou **le vote qu'il annonce** à la banque centrale (cut / hold / hike, et austerity / devaluation en période d'alerte) ; sans chiffres ni vote annoncé, la puce « words only » s'affiche. **Adjourn** quand la négociation est finie.
3. **Close submissions** : dès la clôture, les décisions et les votes de tous les pays deviennent visibles (page étudiants + board). *Run* → **▶ Run year N** (refusé tant que le tour est ouvert) : le modèle rejoue les années 1 à N à partir des décisions enregistrées, des chocs et des votes (un pays sans décision garde sa politique de référence et vote hold / austerity) → aperçu, avec le dépouillement des votes et leur effet → **Save and publish all** : le classement et le panneau de l'union se mettent à jour.
4. *Control* → cocher **Reveal pledges vs decisions for year N** : le tableau « engagements vs décisions » (✓ kept / ✗ broken) s'affiche partout ; il compare les chiffres annoncés aux leviers décidés et le vote annoncé au vote réel.
5. **Next year → N+1**, et on recommence. Les étudiants voient leurs résultats et leurs décisions passées, puis justifient l'année suivante.

**Votes (partie seulement).** Avec ses décisions annuelles, chaque pays vote ; un pays = une voix ; il faut une majorité des pays qui jouent (strictement plus de la moitié des groupes ayant un pays ; un groupe qui ne soumet pas vote « hold » et « austerity »). Les votes restent secrets tant que le tour est ouvert et sont révélés avec les décisions à la clôture.
- **Taux de la banque centrale** (à chaque tour) : *cut / hold / hike*. Une majorité de cut baisse le taux de 0,5 point, une majorité de hike le monte de 0,5 point ; **le changement est permanent** (il se cumule d'un tour à l'autre, jusqu'au vote suivant) et s'ajoute au choc de taux de l'administrateur de l'année ; le taux reste entre 0 et 10 %. Le taux agit sur l'investissement l'année suivante et sur le service de la dette de tous les budgets tout de suite.
- **Crise de réserves — un tour à part, AVANT les décisions.** Quand l'union a fini l'année précédente sous la ligne d'alerte (25 % du stock initial), l'onglet *Control* affiche une carte « Reserves crisis · year N » : **▶ Open the crisis vote** (les soumissions de décisions restent fermées ; la page étudiants ne montre que la question austerity / devaluation) → quand tout le monde a voté, **■ Close the crisis vote and announce** (un pays = une voix, absent groups do not count, la dévaluation exige plus de la moitié des pays). L'issue s'affiche sur la carte, chez les étudiants et sur le board ; mettez-la dans le communiqué, puis **▶ Open submissions**. Austérité → la demande publique et les prestations de **chaque** membre sont plafonnées à −5 % de la référence pour l'année : le formulaire et le backend refusent davantage. Dévaluation → +10 % sur le change au Run de l'année. *Reopen the vote* permet de revoter (les décisions déjà déposées restent). Réserves épuisées **et solde courant encore déficitaire** (R ≤ 0 et CA < 0) → pas de vote, la carte propose **Record the forced devaluation** (15 %) ; dès que le solde courant redevient positif, plus de dévaluation forcée et la question de crise reprend. Le Run rejoue chaque année avec l'issue enregistrée ; s'il constate qu'une année aurait dû avoir un tour de crise non enregistré, il l'indique dans l'aperçu. Point de départ : 3 mois d'importations hors union (100 % de la jauge) ; sans réaction, un choc permanent de −10 % sur la demande mondiale laisse 69 % → 37 % → 7 % → épuisé ; un déficit annuel supérieur au stock restant saute directement l'alerte (par ex. 69 % restants puis une année à −25 %).
L'aperçu de *Run* et le panneau de l'union (console, page étudiants, board) affichent le dépouillement (x cut · y hold · z hike → ±0,5 pt · taux effectif ; x austerity · y devaluation → résultat ; pays plafonnés).

**Réserves et dévaluation.** Le change est fixe : la banque centrale commune couvre le déficit courant de l'union avec ses réserves (3 mois d'importations au départ). Le panneau de l'union (console, page étudiants, board) montre les réserves en mois d'importations et en % du stock initial ; sous **25 %**, l'étiquette **ALERT** apparaît et le tour suivant porte le vote austérité / dévaluation. Vous pouvez aussi décréter une **dévaluation** vous-même : *Run* → champ « Devaluation » de l'année (par ex. 10 = le change saute de 10 %) → **Save shocks** → annoncer dans le communiqué (elle s'ajoute à une éventuelle dévaluation votée). Effets : les importations renchérissent tout de suite (inflation importée), les exportations repartent avec un an de retard (courbe en J).

Le **board** (`Open the board ↗` dans la console) se rafraîchit seul toutes les 15 s ; la page étudiants toutes les 30 s (bouton Refresh aussi).

### Élections (toutes versions du modèle, sans changement du backend)

Dans l'onglet *Run* (partie), sous l'éditeur de chocs, la carte **Elections · voters' preferences from year N** permet de simuler un changement des préférences des électeurs : nouvelles pondérations de la fonction objectif R pour **un pays** ou pour **toute l'union**, à partir de l'année N et jusqu'à l'élection suivante (une élection nationale prime sur une élection de l'union). Deux préréglages — *Left: unemployment first* (0,40 sur le chômage, 0,15 ailleurs) et *Right: public finances first* (0,40 sur le solde public) — et *Back to the class weights* ; les cinq poids restent modifiables librement. Enregistré dans les chocs de l'année (`elections`), donc rejoué comme les autres chocs : le Run calcule le R de chaque pays-année avec les poids en vigueur et les stocke avec le résultat ; la page étudiants affiche « Your objective this year » dans le formulaire, le graphique des contributions utilise les poids de chaque année, le board liste les pays dont les poids diffèrent. Le classement reste la somme des R. Annoncez l'élection dans le communiqué.

**Sixième dimension (v2.0) : les émissions.** Pour une classe en v2.0, R peut inclure les émissions du pays (écart en % à la référence, comptées négativement). Son poids est **0 par défaut** : le dommage se lit déjà dans le chômage et l'inflation, comme bien commun. Il s'active par une élection (préréglage « Green: emissions first » : émissions 0,40, les cinq autres 0,12, pour un pays ou pour toute l'union) ou en modifiant les poids de la classe dans Parameters. Tant qu'il est nul, réduire ses émissions est un bien public : coût pour celui qui le fait, bénéfice pour tous.

### Sortie de l'union (modèles v1.3 et v2.0, backend v1.9 requis)

Spécification : `docs/openmu-spec.md` §12. Désactivée par défaut ; ne rien changer pour une classe qui ne s'en sert pas (sans sortie, le moteur est identique au bit près).

- **Activer** : *Control → Parameters* → cocher **leaving the union allowed (models v1.3 and v2.0)** → *Save parameters*. Refusé (et laissé décoché) si la classe n'est pas en v1.3 ou v2.0.
- **Annonce** : dans son formulaire, une équipe choisit « LEAVE the union at the end of this year » (confirmation demandée ; irréversible). L'annonce reste secrète jusqu'à la clôture, comme les décisions. À la publication de l'année N, la console enregistre `exits = {pays: N+1}` dans l'état de la classe : le pays est hors de l'union à partir de N+1.
- **Chocs propres au pays sortant** (*Run*, sous l'éditeur de chocs, dès l'année de l'annonce) : confiance de ses ménages (%), demande du reste du monde pour ses titres (%, choc d'une année comme « capital flows »), **fuite des dépôts** (points de richesse, durable ; l'année de l'annonce, ce sont les réserves **communes** qui paient ; une valeur négative rapatrie).
- **Conseil de représailles** (*Control*, carte « Council on retaliation against X ») : proposé automatiquement l'année de sortie, avant les décisions ; *Open* ferme les soumissions, les membres restants votent depuis leur page (tarif 0/5/10/20 % sur les exportations de X, vente de 0/25/50/100 % par an des titres de X détenus par la banque centrale de l'union et, si la banque centrale de X doit à l'union, règlement immédiat du solde TARGET) ; *Close and announce* retient la **médiane** des votes (absent = 0). Les mesures restent en vigueur jusqu'à un nouveau conseil (« Convene a council on X » les années suivantes) ; *Open submissions* est refusé tant qu'un conseil siège.
- **Le pays sorti** : levier « Policy rate » (±2 pt), bloc « Your currency » (flottant ou parité contre l'euro, variation de parité ±20 %, rachat par sa banque centrale des titres vendus par l'union), plus de vote au conseil ni de vote de crise ; panneau « Your currency » dans ses résultats.
- **Aperçu du Run** : lignes « X announces its exit » et « X (out of the union): float/peg, … » ; le panneau de l'union, la page des équipes et le board listent les pays sortis et les mesures en vigueur. Les agrégats de l'union (PIB, réserves) portent sur les membres restants.

Ordres de grandeur (France, v1.3, années 2 à 5 après une annonce en année 1) : baisse de 1 pt de son taux en flottant → dépréciation de 11 %, inflation +2,6 pt, PIB −2,3 % puis +1,4 % ; relance de +5 en parité → réserves 90, 78, 64, 47, 29 % de sa part ; tarif de l'union de 10 % → PIB −1,9 % ; vente de la moitié de ses titres par l'union → dépréciation de 12 %. Tests : bloc EXIT de `dev/engine-test.js`, `dev/e2e-exit.js`.

### Droits de douane (backend v1.10 requis)

Spécification : `docs/openmu-spec.md` §13. Désactivés par défaut ; activables en cours de partie (sans tarif, rien ne change).

- **Activer** : *Control → Parameters* → cocher **tariffs** → *Save parameters*.
- **Tarif extérieur commun** : chaque membre vote 0, 5, 10 ou 20 % avec ses décisions (bloc des votes, le niveau en vigueur est proposé par défaut) ; la médiane des votes exprimés s'applique à l'année ; sans vote, le niveau reste. Visible dans l'aperçu du Run, le panneau de l'union et le board.
- **Riposte du reste du monde** : choc *Rest of the world: tariff on union exports* (%) dans l'éditeur de chocs, à poser quand le TEC monte.
- **Pays sorti** : levier *Tariff on goods from the union* (0–20 %) dans son formulaire ; ligne dans son panneau « Your currency ».
- Ordres de grandeur : TEC 10 % → recette ≈ 1,4 % du PIB, solde public +1,2 pt, solde commercial +1,1 pt, PIB −0,6 % (les ménages paient) ; avec une riposte de 10 % → PIB −2 %. L'Italie sortie à 10 % sur l'union → recette +1,6 pt de PIB, PIB +0,8 %, PIB allemand −0,6 %.

### Mode arcade : duels (classe de type `duel`, backend v1.8 requis)

Une variante rapide, sans warm-up ni conseil : **deux pays identiques, A et B**, chacun avec sa monnaie, sa banque centrale et son gouvernement, qui ne commercent qu'entre eux (pas de reste du monde), se prêtent mutuellement des bons (flux de capitaux) et partagent un climat fermé (le stock de pollution n'est alimenté que par leurs deux émissions). Une classe contient **N paires jouées en parallèle** : chaque paire est un monde à part, les chocs de l'année s'appliquent à toutes les paires, un seul *Run* simule toutes les paires. Le modèle est fixé à v2.0 (deux économies v2.0 complètes, le partenaire remplaçant le reste du monde).

- **Créer la classe** : *+ New class* → nom, puis à la seconde question « Kind of class » répondre `duel`. La classe démarre directement en partie, en année 1, tour fermé ; pas de phase de warm-up, pas de conseil, pas de vote de crise.
- **Groupes** : onglet *Groups* → **Add N pairs** (crée « Pair 1 · Country A », « Pair 1 · Country B », …). Le pays d'un groupe est `p<k>:A` ou `p<k>:B` ; on peut aussi le choisir dans la liste.
- **Leviers** : les six de v2.0 (dépenses, transferts, taxes, austérité, taxe carbone, investissement vert) **plus le taux directeur** (`rate`, en points autour de 3 %, ±2 ; pas 0,25). Pas de vote sur le taux : chaque joueur fixe le sien. Un ancien backend refuse ce levier (« belongs to the duel mode »).
- **Régime de change** (choc `Exchange-rate regime`, par année, toutes paires) : en **fixe**, les deux banques centrales défendent la parité ; le pays en déficit de balance des paiements perd des réserves (3 mois d'importations au départ) et le pays en excédent en gagne ; alerte sous 25 % ; réserves épuisées avec un déficit courant qui continue → **dévaluation forcée de 15 %** de cette monnaie, automatique, l'année suivante. En **flottant**, le taux bilatéral e (monnaie de A par unité de B) équilibre la balance des paiements et les réserves ne bougent plus. L'administrateur peut aussi décréter une **dévaluation de A ou de B** (chocs `devalA`, `devalB`, régime fixe seulement).
- **Chocs** (toutes paires) : confiance, propension à importer, **demande en A / demande en B** (% de la demande publique, pour casser la symétrie : catastrophe −, boom +), régime, dévaluations, backstop de la banque centrale (chaque pays a la sienne), catastrophe climatique. Pas de choc d'émissions mondiales (il n'y a pas de reste du monde).
- **Élections** : portée « Every player », « Every Country A », « Every Country B » ou un pays précis.
- **Run year N** : aperçu compact par paire (les deux pays + la ligne de paire : e, régime, réserves A et B, CA′, pression, S, D) puis *Publish*. L'onglet *Results* liste les deux pays de chaque paire.
- **Page étudiants** : sept leviers, pas de vote ; après publication, carte « Your duel · pair k » (régime, e et sa variation, barres de réserves des deux pays, taux directeurs, climat), tableau du partenaire, quatre lignes « of which » (your own policy / **your partner's policy** / the shocks / the climate), les deux graphiques côte à côte, classement de tous les joueurs avec vous et votre partenaire surlignés, décisions de la paire seulement.
- **Board** : grille des paires (un panneau par paire) + classement global.

Ordres de grandeur (année 1, A seul relance de +10 % de dépenses, fixe) : PIB A +2,7 %, PIB B +1,0 % (par les importations de A), réserves de A 93 % puis 84, 74, 64, 52, 40, 28 % → alerte en année 8 (3 mois de réserves, avoirs croisés 15 % du PIB). En flottant, la même relance déprécie la monnaie de A de 3,9 % en année 1 et 23 % en année 5. Une hausse de 1 point du taux de A en flottant apprécie sa monnaie de ~7 % : PIB A +1,8 % puis −1,7 %, B −1,9 % puis +0,3 %. Une taxe carbone de 5 points en A seul réduit ses émissions de 70 % en cinq ans et le dommage commun de 7 à 5,5 % : A paie, les deux en profitent.

**Tests** : `node dev/engine-test.js` (bloc DUEL : stationnarité, identités comptables et balance des paiements bilatérale sur 20 graines × 20 ans, dévaluation forcée) et `node dev/e2e-duel.js` (scénario complet sur le serveur fictif).

## 3. Paramètres (onglet *Control* → *Parameters*)

| Paramètre | Défaut | Remarque |
|---|---|---|
| Bornes : leviers | ±10 % | **les 4 leviers sont des variations relatives, en %, de la référence propre au pays** (0 = pas de changement) ; validées côté page et côté serveur. Tarifs, euro et PGF : hors OPEN-MU v1, laissés désactivés |
| Warm-up : pays, années, instruments autorisés, nb max d'instruments, texte min. | France, 3, les 4 leviers, 4, 150 car. | un instrument « utilisé » = non nul sur au moins une année |
| Partie : nb max d'instruments, texte min., nombre d'années | illimité, 100 car., 5 | une décision « tout à zéro » est acceptée dans la partie (ne rien faire est une stratégie : passager clandestin) |
| Visibilité des décisions | masquées tant que le tour est ouvert ; visibles de tous dès que le tour est clos | case « once a round is closed, show everyone's decisions » dans *Control* ; les engagements du conseil sont publics par construction, les justifications restent privées |
| Poids de la fonction objectif | 0,2 partout (vos diapos) | R = Σ poids × écart, signes négatifs sur le chômage et l'inflation ; calculé par la console à partir des 5 écarts du modèle |
| Version du modèle | **v1.2** pour toute classe créée depuis le 05/11 au soir (niveaux de prix dans les échanges avec un an de retard, réserves initiales 1,5 mois) ; v1.1 pour les classes antérieures et celles sans la clé (séance 6 : pas de canal prix, 3 mois) | Control → Parameters → « Model version » ; une partie en cours doit garder sa version (le Run rejoue toutes les années avec le moteur choisi) ; `state.sim.model` |
| Votes | activés ; pas de 0,5 pt ; plafond d'austérité −5 % ; dévaluation votée 10 % ; dévaluation forcée 15 % ; (v1.3, change flottant) crise de change si dépréciation > 10 % dans l'année, « defend » = +1 pt sur le taux | case « votes enabled » pour jouer sans les votes ; enregistrés dans `state.sim` |

R = a₁·ΔPIB − a₂·Δchômage − a₃·Δinflation + a₄·Δsolde public + a₅·Δsolde commercial, écarts à l'état stationnaire de référence du modèle : PIB en %, chômage et inflation en points (thermomètres d'Okun et de Phillips posés sur le modèle), soldes public et commercial en points de PIB. R est le **score de l'année** (écarts de l'année, pondérés), pas une variation d'une année sur l'autre ; le **R cumulé** est la somme des scores annuels (colonne « Cumulative R » / « Cum. R » partout, avec la même décomposition propre / étranger / chocs). Le classement de la partie et le débrief du warm-up trient sur le R cumulé. La décomposition « propre / étranger / chocs » est obtenue par simulations contrefactuelles (chocs seuls ; chocs + politique du pays seul ; tout).

## 4. Dépannage

- *Invalid administrator key* : la clé est dans l'onglet `Config` de la Sheet (ligne `adminKey`).
- *Cannot reach the server* chez les étudiants : `API_URL` manquant dans `config.js`, ou déploiement non public (« Qui a accès : Tout le monde »).
- Les pages fonctionnent aussi sans `config.js` renseigné : ajouter `?api=URL_DU_SCRIPT` à l'adresse (utile pour tester avant le push).
- La Sheet est la vérité : tout est append-only (la dernière ligne par groupe/tour l'emporte), l'onglet `Log` trace chaque action. Vous pouvez la consulter pendant la séance sans rien casser ; évitez d'y écrire à la main.
- Un groupe a perdu son PIN : onglet *Groups* de la console.
- Supprimer une classe (par ex. une classe de test) : bouton **Delete class…** dans la barre du haut de la console ; il faut retaper le nom exact de la classe. Ses groupes, PIN, décisions, résultats, engagements et analyses sont retirés de la Sheet (les autres classes ne bougent pas). Irréversible.
- « engine not loaded » dans l'onglet *Run* : `macroscope/engine.js` manque sur le site ou n'a pas chargé ; recharger la page. Les résultats restent saisissables à la main dans *Results*.
- « Close the round first » : le bouton Run year refuse de tourner tant que les soumissions sont ouvertes (*Control* → **Close submissions**).
- Les chocs ne s'enregistrent pas, ou les votes sont refusés / absents des décisions : le script Apps Script n'est pas en v1.3 au moins (voir le pied de page de la console) ; les votes annoncés au conseil disparaissent des engagements : script en v1.3, il faut la v1.4 ; le vote de crise (« The crisis vote is not open ») et le plafond d'austérité exigent la v1.5 ; recoller `Code.gs` et republier une version.
- La question « austerity or devaluation » n'apparaît pas chez les étudiants alors que l'union est en alerte : l'année précédente n'a pas été **publiée** (Save and publish all), ou la page n'a pas été rafraîchie.
